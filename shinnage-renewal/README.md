# SHINNAGE(신나게) 리뉴얼

천천히 오래 가는 홈페이지를 목표로 했습니다. 방문자가 몰리지 않아도 꺼지지 않고, 유지비가 거의 들지 않으며, 한 달에 한 번 사람들이 돌아올 이유가 있는 구조입니다.

- 미리보기: `public/index.html`을 브라우저로 열면 됩니다.
- 원본 소스: `src/body.html` (수정 후 `scripts/build.sh` 실행)

---

## 1. 왜 꺼졌나

기존 사이트는 Supabase **무료 플랜**을 쓰고 있고, 무료 플랜은 **7일 동안 활동이 없으면 프로젝트를 자동으로 일시정지**합니다. 신규 유입이 없으니 DB가 잠들었고, 홈페이지가 DB에 의존하고 있어서 사이트 전체가 멈춘 것처럼 보였습니다.

## 2. 해결 원칙

| 원칙 | 방법 |
|---|---|
| DB가 잠들어도 홈페이지는 살아 있게 | 홈페이지를 **정적 페이지**로 분리. 시즌 정보 등은 코드 안에 둠 |
| DB가 잠들지 않게 | 사흘마다 DB를 한 번 읽는 **keep-alive** (GitHub Actions 또는 Cloudflare Worker) |
| 영상 비용 0원 | 영상 파일은 올리지 않고 **YouTube 링크만** 연결 (기존 방식 유지) |
| 무거운 배경 영상 제거 | 기존 장르 카드의 mp4 6개를 CSS 그래픽으로 교체 → 트래픽 비용·로딩 속도 개선 |

## 3. 예상 유지비

| 항목 | 서비스 | 비용 |
|---|---|---|
| 홈페이지 호스팅 | Cloudflare Pages (트래픽 무제한) | 0원 |
| DB·로그인 | Supabase Free + keep-alive | 0원 |
| 영상 | YouTube 링크 | 0원 |
| 월간 레터 발송 | 무료 플랜이 있는 뉴스레터 서비스 (구독자 수백 명까지) | 0원 |
| 도메인 | .com 등 | 연 약 1.5만~2만 원 |
| **합계** | | **연 약 2만 원** |

> Supabase Pro($25/월)로 올리면 자동 정지는 없어지지만, 지금 단계에서는 keep-alive로 충분합니다.

## 4. 오래 가는 구조: 폭발 대신 리듬

1. **월간 시즌 무대**: 매달 주제 하나(10월 가을 버스킹, 11월 클래식의 밤…). 매달 "이번 달 무대"가 바뀌니 다시 올 이유와 SNS에 올릴 소식이 자동으로 생깁니다. 참가작이 3편뿐이어도 '큐레이션'처럼 보입니다.
2. **두 가지 입구**: 재능이 있는 사람(크리에이터)뿐 아니라 **보는 사람(평가자)**도 가입할 이유가 있습니다. 평가자가 훨씬 많은 잠재 사용자층이에요.
3. **꽃 평판**: 새싹 → 봉오리 → 꽃 → 만개. 좋은 무대를 먼저 알아본 사람의 안목이 쌓이니 꾸준히 들어올 동기가 됩니다.
4. **월간 레터**: 사이트에 자주 오지 않아도 한 달에 한 번 메일로 연결이 유지됩니다. 유입이 적을 때 가장 효율적인 재방문 장치입니다.
5. **크리에이터가 곧 홍보 채널**: 무대를 올린 사람은 자기 공연 링크를 스스로 공유합니다. 출연자 한 명 한 명이 유입 경로가 됩니다.
6. **아카이브**: 지난 시즌 무대가 계속 쌓여 검색 노출(SEO) 자산이 됩니다.

## 5. 운영자 월 2시간 루틴

| 시점 | 할 일 | 시간 |
|---|---|---|
| 매달 1일 | 새 시즌 주제 SNS 공지 (주제는 `src/body.html`의 `SEASONS`에 1년치 미리 작성됨) | 20분 |
| 매달 15일 | 참가작 중간 소개 1회 | 20분 |
| 매달 7일 | 이달의 무대 3편 발표 + 월간 레터 발송 | 60분 |
| 수시 | 들어온 무대 확인 | 20분 |

## 6. 배포 방법

1. **DB 깨우기**: Supabase 대시보드에서 일시정지된 프로젝트를 Restore합니다.
2. **테이블 만들기**: SQL Editor에서 `supabase/schema.sql`을 실행합니다. (레터 신청자 테이블은 '추가'만 가능하도록 RLS가 설정됨)
3. **설정**: `public/config.js`에 Supabase URL과 anon key를 넣습니다.
4. **호스팅**: Cloudflare Pages에서 이 저장소를 연결하고, 빌드 명령 없이 출력 폴더를 `shinnage-renewal/public`으로 지정합니다.
5. **keep-alive**: 아래 둘 중 하나를 고릅니다.
   - GitHub Actions: 저장소 Settings → Secrets에 `SUPABASE_URL`, `SUPABASE_ANON_KEY`를 추가합니다. (`.github/workflows/shinnage-keepalive.yml`)
     단, **공개 저장소는 60일간 커밋이 없으면 GitHub이 예약 작업을 꺼 버립니다.** 경고 메일이 오면 다시 켜 주세요.
   - Cloudflare Worker Cron (권장, 꺼질 걱정 없음): `scripts/keepalive-worker.js` 안의 안내를 따르세요.
6. 기존 Next.js 앱의 `/creator/start`(무대 등록)와 `/performances`(둘러보기)는 그대로 쓰고, 이 페이지를 메인(`/`)으로 연결합니다.
