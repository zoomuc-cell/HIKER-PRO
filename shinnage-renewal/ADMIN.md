# SHINNAGE 가입자 관리 가이드 (관리자용)

신나게는 폭발적인 유입보다 **천천히, 오래** 가는 구조입니다. 그래서 가입자 관리의 핵심은 많이 모으는 것보다 **한 명도 흘리지 않고, 매달 한 번 확실히 연결되는 것**입니다.

---

## 1. 가입자 여정과 관리 활동

| 단계 | 가입자에게 일어나는 일 | 관리자가 할 일 | 확인하는 숫자 |
|---|---|---|---|
| **유입** | SNS·포스터·지인 링크로 홈페이지 방문 | 채널마다 링크 끝에 `?from=이름`을 붙여 배포 | `admin.letter_sources` |
| **가입** | 월간 레터 신청 | 매주 신규 가입 확인 | `admin.letter_summary`의 `new_7d` |
| **환영** | 가입 직후, 첫 레터 전까지 공백 | 뉴스레터 서비스의 환영 메일 자동 발송 설정(1회) | 환영 메일 오픈율 |
| **연결** | 매달 7일 레터 수신 | 레터 발송 (아래 4번 절차) | 오픈율, 클릭 수 |
| **참여** | 꽃 건네기 / 무대 올리기 | 레터에서 이번 시즌 참여 링크 안내 | 시즌 참가작 수 |
| **이탈** | 수신 거부 | 사유 파악, 즉시 파기 확인(자동) | `unsub_30d`, `admin.letter_monthly` |

### 유입 경로 링크 만들기
같은 홈페이지 주소라도 뒤에 붙인 이름으로 어디서 왔는지 구분돼요.

| 채널 | 배포할 링크 예시 |
|---|---|
| 인스타그램 프로필 | `https://도메인/?from=insta` |
| 카카오톡 공유 | `https://도메인/?from=kakao` |
| YouTube 설명란 | `https://도메인/?from=youtube` |
| 오프라인 포스터 QR | `https://도메인/?from=poster` |
| 크리에이터 본인 공유 | `https://도메인/?from=creator` |

이름을 붙이지 않은 링크는 들어온 사이트 주소가 기록되고, 주소창에 직접 입력하면 `(직접 방문)`으로 집계돼요.

## 2. 관리 루틴

### 매주 월요일 (5분)
Supabase → SQL Editor → New query:
```sql
select * from admin.letter_summary;
```
- `new_7d`: 지난 7일 신규 가입자
- `unsub_30d`: 최근 30일 수신 거부 수. 갑자기 늘면 직전 레터 내용을 돌아보세요.

### 매달 1일 (15분): 지난달 돌아보기
```sql
select * from admin.letter_monthly;   -- 월별 가입 / 이탈 / 순증 / 누적
select * from admin.letter_sources;   -- 채널별 가입·이탈
```
- **가입이 가장 많은 채널**에 이번 달 홍보를 집중합니다.
- **가입 대비 이탈이 높은 채널**은 기대와 실제 내용이 어긋난 곳이에요. 그 채널의 소개 문구를 고칩니다.

### 매달 7일 (60분): 레터 발송
4번 절차를 따릅니다.

---

## 3. 목표 수치 (첫 6개월 기준)

| 지표 | 목표 | 위험 신호 |
|---|---|---|
| 시즌 1 오픈(12월 1일) 전 가입자 | 50명 | 30명 미만이면 오픈 공지 홍보 강화 |
| 월 순증 | +20명 | 2개월 연속 0 이하 |
| 월 이탈률 (`left_` ÷ 전월 누적) | 2% 이하 | 5% 이상 |
| 레터 오픈율 (뉴스레터 서비스 통계) | 40% 이상 | 25% 미만이면 제목·발송 시간 조정 |

가입자 수가 적을 때는 비율이 크게 흔들리니, **3개월 추세**로 판단하세요.

## 4. 월간 레터 발송 절차

1. **목록 내보내기**: SQL Editor에서 실행한 뒤 결과 창의 Export → CSV로 내려받습니다.
   ```sql
   select * from admin.letter_export;
   ```
2. **뉴스레터 서비스에 업로드**: 이메일 열, 그리고 `unsubscribe_token` 열을 사용자 정의 필드로 올립니다.
3. **수신 거부 링크**를 레터 하단에 넣습니다. 서비스의 개인화 필드 문법으로 토큰을 끼웁니다.
   ```
   https://도메인/unsubscribe.html?t={{unsubscribe_token}}
   ```
4. **발송 후 정리**
   - 내려받은 CSV 파일은 발송이 끝나면 **바로 삭제**합니다.
   - 뉴스레터 서비스 자체의 수신 거부 버튼으로 거부한 사람이 있으면, 다음 업로드 전에 그 이메일을 Supabase에서도 지웁니다.
     ```sql
     delete from public.letter_subscribers where email = '거부한주소@example.com';
     ```

### 레터 구성 (매달 같은 틀)
1. 이달의 무대 3편 (꽃을 가장 많이 받은 순)
2. 먼저 발견한 평가자 한 명 소개
3. 다음 시즌 주제와 접수 마감일
4. 참여 버튼 두 개: "무대 올리기" / "꽃 건네러 가기"

---

## 5. 개인정보 체크리스트

- [ ] 수집 목적(월간 레터 발송) 외에는 이메일을 쓰지 않는다.
- [ ] 수신 거부는 자동으로 즉시 삭제된다. 숫자 통계에는 이메일이 남지 않는다.
- [ ] 외부 뉴스레터 서비스를 쓰면 개인정보처리방침에 **처리 위탁 업체명**을 적는다.
- [ ] 내려받은 CSV는 발송 후 삭제한다.
- [ ] 레터에 홍보·광고 성격의 내용이 들어가면 제목에 `(광고)` 표기 등 정보통신망법 요건을 확인한다.

## 6. 데이터 구조 요약

| 이름 | 내용 | 접근 |
|---|---|---|
| `public.letter_subscribers` | 이메일, 관심 역할, 유입 경로, 수신 거부 토큰 | 방문자는 **추가만**, 조회 불가 |
| `public.letter_unsubscribe(토큰)` | 토큰이 맞으면 해당 이메일 즉시 삭제 | 누구나 호출 가능 (토큰을 아는 본인만 의미 있음) |
| `admin.letter_events` | 가입·이탈 기록 (이메일 없음) | 관리자만 |
| `admin.letter_summary / monthly / sources / export` | 관리자 보기 | 관리자만 (API에 노출 안 됨) |
